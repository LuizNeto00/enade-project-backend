## Description

[Nest](https://github.com/nestjs/nest) framework TypeScript starter repository.

## Project setup

```bash
$ cp .env.example .env
# Replace the placeholder database passwords in .env before starting the stack.
$ docker compose up --build
```

The Compose stack binds the MySQL port to localhost only. Database credentials
are supplied through `.env`; do not commit that file. For a local API process
outside Docker, set `DB_HOST=localhost` in `.env`.

## Simulados em PDF

Execute as migrations no banco de desenvolvimento antes de usar o módulo:

```bash
docker compose exec api npm run typeorm:migration:show
docker compose exec api npm run typeorm:migration:run
```

O professor envia `examPdf` e `answerKeyPdf` como campos separados de
`multipart/form-data`. O limite por arquivo é configurado em bytes por
`MOCK_EXAM_MAX_PDF_SIZE_BYTES` (padrão: 50 MiB). São aceitos apenas PDFs não
criptografados com extensão, MIME, assinatura e estrutura legíveis.
O endpoint autenticado `GET /mock-exams/teacher/upload-config`, exclusivo para
professores, informa `maxPdfSizeBytes` para a validação do formulário.

Alunos podem combinar os parâmetros opcionais `search`, `examYear` e `course`
em `GET /mock-exams/student`. A busca encontra trechos do título ou do código;
a listagem e o acesso direto continuam restritos a simulados ativos.

Os documentos são armazenados no volume Docker `mock_exam_pdfs`, fora do
diretório público de uploads. Preserve e inclua esse volume nos backups;
remover volumes do Compose também remove os documentos. Acesso à prova exige
autenticação e, para alunos, status ativo. O gabarito do aluno exige também
uma conclusão voluntária registrada no banco. O cronômetro permanece no
navegador e não determina a conclusão ou o acesso à prova.

Os endpoints de documentos retornam PDFs completos autenticados, sem suporte
HTTP Range nesta versão.

## Compile and run the project

```bash
# development
$ npm run start

# watch mode
$ npm run start:dev

# production mode
$ npm run start:prod
```

## Run tests

```bash
# unit tests
$ npm run test

# e2e tests
$ npm run test:e2e

# test coverage
$ npm run test:cov
```

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash
$ npm install -g @nestjs/mau
$ mau deploy
```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.
